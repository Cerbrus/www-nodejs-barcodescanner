## Defects

### 1. The updater skips rollbacks

Since 1.1.102 `deployment/update.sh` stops early when the local image for the wanted tag has the registry's digest and as many containers run as the compose file has images. It never looks at which image the containers run.

- With `IMAGE_TAG` pinned to a version whose image is still on the Pi, the check says "current" and nothing happens. Established on the Pi without changing anything: the check, run with `IMAGE_TAG=1.1.77` while 1.1.102 was running, answered that it would exit early. The images of 1.1.77 and 1.1.56 are on the Pi.
- Going back to `latest` after a rollback is skipped the same way, as long as no new release came in between.
- A run that pulled the images but failed to restart leaves the old containers running, and every later run calls that current.
- The rollback test in `deployment.md` passed on 2026-11-15, before this change; its instruction, set `IMAGE_TAG` and run the updater, no longer holds.
- The card scanner's updater has the same check and the same flaw.

A fix has to compare what runs with what is wanted. Comparing image ids alone is not enough: every build gives the hardware agent's image a new manifest id with the same content, and Compose rightly leaves that container running (seen on the Pi on 2026-11-16).

### 2. The naming prompt can link a barcode with the wrong variant

The variant field is filled from the proposal's note, for instance "Halfvolle" for Melk. `choose()` sends that field for whichever product is chosen: the proposed one, another from the search, or a new product from the form. Ignoring the proposal and picking Karnemelk links the barcode to Karnemelk with variant "Halfvolle", unless the field is emptied by hand. The field is also overwritten when the lookup's answer arrives while the user types. Established by reading `naming-prompt.component.ts` and its template.

## Smaller issues

- **What the updater no longer does.** Until 1.1.102 every run, each 5 minutes, ended in `docker compose up -d` and `firewall.sh`, so a changed `.env` and a lost firewall rule were put right by themselves. Now that happens only when a release arrives and at boot, and a run by hand stops early as well. `deployment.md` describes the updater without the early stop in its paragraph on `update.sh`.
- **Cost of running every minute.** About 2.6 seconds of processor time per run on the Pi 3, for each of the two projects, and four script files written to the SD card per run.
- **Sound editor, empty name.** With an existing sound, Save stays enabled when the name is empty; the server then refuses it. Through the API, changing a sound without a name removes a name the owner gave, after which the page shows the text key.
- **Offline changes without an id.** A change in `POST /api/v1/list/offline-changes` with neither `id` nor `catalogItemId` answers 500 instead of 400: TypeORM 1 throws on an undefined value in a query, where 0.3 skipped it. Every other query in the API was read for this; none passes a value that can be undefined or null.
- **Section for sauces and oil.** Albert Heijn's category "Soepen, sauzen, kruiden, olie" maps to Gereed & diepvries, because "soep" is tried first; Ingrediënten & kruiden fits its content better. A test fixes the present answer.
- **One `!` left.** `!justify-start` in the new-product form still works in Tailwind 4, but is the old spelling and no longer needed since the shared classes sit in a layer. The report at the time said all were gone.
- **Docs.** `plan.md` says "Where it stands" at 1.1.87. `decisions.md` has no entry for the sound at a new version, nor for the Prettier choices (no trailing commas, `bracketSameLine` off, Angular parser).
- **The update sound also plays** after a rollback and on a first install, as any version other than the last one announced counts as new. Not decided whether that is wanted.
